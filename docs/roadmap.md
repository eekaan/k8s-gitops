# Roadmap

Milestones in the order they are built. A state is read from the tree, not from a running cluster:
a milestone is `done` when every part of its outcome sentence is delivered by the tree and a
recipe, a check or a runbook shows it; `in progress` when some parts are and others are not; and
`not started` when none is. "Shown by" names what delivers it, and for a milestone in progress,
what is not delivered.

| | Milestone | State | Outcome | Shown by |
|---|---|---|---|---|
| M0 | Foundations | done | The repository validates itself; nothing is deployed. | `just ci` runs the checks that need no credentials and run in CI, locally and as the required check `ci` on a pull request; `just check-literals` fails a committed address literal and `just lint` a broken file. |
| M1 | Infrastructure | done | Two stacks, the plumbing stack before the cluster stack, give six virtual machines waiting for Talos configuration, whose Talos and Kubernetes APIs admit only the operator's networks, the cluster's own addresses and, where one is configured, the CI host. | `just infra-apply sto2/plumbing` and then `just infra-apply sto2/cluster` make them ([Recipes](infrastructure.md#recipes)); `just infra-check` plans the cluster stack offline, against mocked providers, and shows three control planes and three workers without user data, admitting from outside the nodes only the Talos and Kubernetes API ports from the allowlist and the nodes' own floating addresses and the Kubernetes API port from the node subnet, and both ports from the CI host's address once the stack is given its host number ([The nodes' security group](infrastructure.md#the-nodes-security-group)). |
| M2 | Cluster | done | One command gives six Ready nodes with Cilium, repeatable from nothing. | `just cluster-bootstrap` ends when every node is Ready and `just cluster-check` finds no kube-proxy; `just cluster-reboot` fails a control-plane reboot that interrupts the API; `just cluster-destroy` and [the rebuild runbook](runbooks/rebuild.md) take it to nothing and back; `just talos-check` renders every node's configuration offline ([cluster.md](cluster.md)). |
| M3 | GitOps core | done | A merge to `main` reconciles the cluster from a signed artifact, and an unsigned one is refused. | The publish workflow's `just publish` signs the artifact and moves the `main` tag only after `just kubernetes-check` passes; the FluxInstance's source verifies that signature and refuses any other (`tests/flux.bats`); `just render-diff` is the comment every pull request gets ([kubernetes.md](kubernetes.md#publishing)). |
| M4 | Platform services | in progress | An application gets, from Git alone, a volume from LINSTOR, a secret from OpenBao through External Secrets, and a hostname the world resolves, served by the public Gateway behind the edge routers with a certificate from cert-manager that clients outside the cluster trust. | Delivered: the `demo` applications and n8n take a replicated volume, a secret from the store and a route on the Gateway, whose certificate cert-manager issues from the issuer the cluster's overlay chooses, the cluster's own CA or Let's Encrypt by DNS-01 ([The ACME issuers](kubernetes.md#the-acme-issuers)); external-dns publishes each route's name at both edge routers' public addresses ([DNS records](kubernetes.md#dns-records)); `just gateway-check` proves the path through each edge router, checks the certificate against the trust its issuer implies and that each name resolves to both edges, and `just cluster-destroy` refuses while the cluster owns a load balancer or a cloud volume. `lab-sto2` chooses Let's Encrypt's production issuer, whose certificates a client with the usual public roots trusts. Not delivered: reaching the hostnames from anywhere, as the edge routers admit the public ports from the operator's networks only while `public_allowed_cidrs` is unset ([The edge routers](infrastructure.md#the-edge-routers)). |
| M5 | Observability | in progress | A broken node, application or reconcile reaches the operator. | Prometheus, Alertmanager, Grafana and the log store run and are checked (`just cluster-check` for scrape targets, `just rules-check` for the alert rules with tests that fire and stay quiet, `just vector-check` for the log collector's configuration), Grafana's dashboards, a home dashboard among them, come from Git and are checked by `tests/dashboards.bats` ([Dashboards](kubernetes.md#dashboards)), and `just logs` and `just grafana` read them. Not delivered: a destination for alerts, as Alertmanager sends them nowhere, and an alert on a reconcile, as nothing scrapes Flux. |
| M6 | Data and backups | in progress | Losing the cluster loses no data. | Etcd snapshots, encrypted before upload, taken every six hours by a CronJob whose two alerts fire when its runs stop succeeding ([Scheduled etcd snapshots](cluster.md#scheduled-etcd-snapshots), `tests/etcd-snapshots.bats`) and by `just cluster-snapshot`, and put back by `just cluster-restore` ([the runbook](runbooks/etcd-restore.md)); volume backups with VolSync's restic mover, of n8n's and `volsync-demo`'s volumes ([volume-backups.md](runbooks/volume-backups.md)), restored by the runbook; WAL archiving and daily base backups of each PostgreSQL database made from the cluster template, n8n's among them, through the Barman Cloud plugin to the `postgres` bucket, encrypted at the provider with a customer key, whose two alerts fire when archiving fails or the newest base backup is too old ([Backups and restores](kubernetes.md#backups-and-restores), `tests/postgresql.bats`), restored to a point in time into a new cluster by [the runbook](runbooks/postgres-restore.md); daily dumps of each such database, encrypted with age before upload, whose two alerts fire when they stop succeeding ([Dumps](kubernetes.md#dumps), `tests/postgres-dumps.bats`), restored into a new cluster by the same runbook; OpenBao raft snapshots of the secret store, encrypted with age before upload, taken every six hours by a CronJob whose two alerts fire when its runs stop succeeding and restorable into a store that unseals with the same seal key ([Raft snapshots](kubernetes.md#raft-snapshots), `tests/openbao-snapshots.bats`, [the runbook](runbooks/openbao.md#restoring-a-snapshot)); the rebuild runbook says what survives. Not delivered: backups of the monitoring and log volumes, and a restore of them into a rebuilt cluster. |
| M7 | Workloads | in progress | The services the cluster exists for. | Delivered: n8n, the first application of the reference catalogue, in `ai-system`, with its database from the PostgreSQL template, its volume backed up, its encryption key from the secret store and a route on the public Gateway (`tests/applications.bats`, [n8n](kubernetes.md#n8n)); Open WebUI, a chat interface, in the same namespace, with its volume backed up and a route on the public Gateway ([Open WebUI](kubernetes.md#open-webui)); the `demo` applications exist to prove the platform. Not delivered: the reference catalogue's other applications ([Porting an application from the reference catalogue](kubernetes.md#porting-an-application-from-the-reference-catalogue)). |
| M8 | Hardening and automation | in progress | Infrastructure and upgrades run without a laptop; the cluster is locked down. | Delivered: the nodes' own firewall ([cluster.md](cluster.md#the-node-firewall)), Pod Security levels enforced and checked by `just pod-security-check`, the namespaces' default deny with their allows in `backstage`, `crowdsec`, `demo`, `envoy-gateway-system`, `kromgo`, `security-system` and `sso-system`, every other namespace listed with its reason, checked by `just network-policy-check` ([Network policy](kubernetes.md#network-policy)), and a CI host that runs the checks. Not delivered: planning and applying infrastructure from CI, and Talos and Kubernetes upgrades from CI, as no workflow runs `cluster-upgrade`, `infra-plan` or `infra-apply`; and network policy that drops anything, as Cilium audits every policy, cluster-wide, and drops nothing ([Service addresses](kubernetes.md#service-addresses)). |

The decisions behind this order are in [`docs/adr/`](adr/).
